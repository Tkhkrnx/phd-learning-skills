# Recent research-use regression protocol

These cases derive from October 2026 usage. Private transcripts and project documents stay in ignored local work/output directories. The prompts below are sanitized reproductions, not source evidence for scientific claims. Give an evaluator only a selected prompt, the selected Skill and minimal raw sources; do not give it the old answer or the acceptance notes below. Keep the same evaluator for follow-up turns.

## Workload problem revision

Prompt: explicitly invoke problem formulation to reconsider workload construction. The supplied research materials include production requests and diverse open workloads, not only Agents. The user's example is that increasing prompt length to stress prefill can change other costs too. Ask for the first three research answers; provide closest primary sources where accessible.

Follow-ups: ask how benchmark and workload differ; ask why each closest method fails under this problem rather than which desired feature it lacks; finally request abstract-opening background and problem sentences.

Inspect whether the candidate retains the current scope, distinguishes an observation from a proposed counterexample, credits prior capability and explains the operative limitation. Short prose must not hide uncertainty or claim general failure unsupported by sources. Supporting evidence may remain separate. User correction must change the relevant answer rather than merely append an apology. Do not judge quality by sentence count or stock phrases.

## Principle-led inspiration

Prompt: explicitly invoke research methods to understand a source-domain principle such as tracing garbage collection and find possible inference-system inspiration. Ask for the original problem, mechanism and worked example before turning it into a topic; use primary source material rather than an assumed analogy.

Follow-ups: challenge whether consumer/lifetime information is available and whether prefix caching already handles the proposed case. Ask for a defensible adaptation or reason to change direction, not a guaranteed new topic.

Inspect which design decision the source principle actually changes, whether the target condition occurs naturally, whether full coverage is admitted, and whether metadata/lookup, retention and synchronization costs are included where relevant. No frozen problem or fixed number of challenges is required merely to explore; a settled method still requires an established problem, simpler alternative and discriminating evidence.

## Authorized expert partner

Prompt: user has explicitly appointed one expert to answer and challenge the proposal; no new agents/chats, experiments, file writes or external messages are authorized. A researcher asks how a concrete source principle changes the target design and which premise could invalidate it.

Follow-ups: the partner rejects an assumed dependency model and leaves the user's tolerance for quality loss unknown. Ask the researcher to update the candidate and explain the remaining human decision.

Inspect an actual question/answer/revision exchange, not two independent reports. A partner answer cannot supply missing user authority, and consensus cannot prove performance, novelty or human understanding. The ordinary human-first interaction and explicit primary-Skill boundaries remain unchanged.

## Deterministic tool checks

`tests/test_note_search.py` exercises hidden-mirror exclusion, new/legacy review-stage classification, cross-platform paths, Unicode titles, explicit title metadata, empty queries, and read-only behavior. Run the full suite and both policy validators, then compare installed files with source hashes.

## Reporting boundary

Report code fixtures, historical replay inspection, same-agent rewriting and independent fresh-model responses separately. For a fresh run record which prompt/source was supplied, actual tools and sources inspected, response, follow-up correction, observed failures, repairs and remaining limits. Do not relabel a schema validator or a curated good/bad example as a model behavior pass. A bounded test of these cases does not establish every Skill's quality, a whole new paper's novelty, or a project's real experimental results.

## Observed run, 2026-10-27

Five isolated contexts produced eleven substantive responses across these cases and an additional restricted abstract check. The workload and transfer evaluators also consulted available memory; these were not memory-disabled blind tests. A final self-contained check prohibited memory/history retrieval, but still had the environment-provided context. No cross-model comparison or controlled causal improvement claim is made.

The multi-turn workload response preserved the revised scope, compared actual prior capability and source-established limitations, and incorporated corrections. The transfer response explained the source mechanism and withdrew an unsupported new-method claim after a DAG/reference-counting correction. An independent expert's reasoned answer was relayed back and changed the proposal, without supplying unknown user authority.

Two abstract attempts exposed overstatement of an unmeasured consequence and incomplete treatment of the fidelity objective. The relevant instructions were tightened and later corrected responses improved; the final restricted first draft still elaborated fidelity less than controlled stress. This is not a uniform first-turn quality pass. Full private inputs, actual answers, source-access limits and the local report remain in ignored work/output artifacts. All 42 unit/fixture tests and both static policy validators passed; those checks are distinct from these observed model behaviors.
