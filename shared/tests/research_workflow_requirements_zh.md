# 研究、工程和学习 Skill 的综合要求

这份清单供用户验收，也供维护者在精简入口时核对。日常调用从各 Skill 的入口开始。

## 调用与协作

用户明确说“用研究问题的 skill”之类的话就能调用，中文名称有效。同一目标下可以接着讨论。主 Skill 为回答当前疑问可以借用论文搜索，Finder 也可独立使用。长期任务按用户指定的阶段调用；落实已选方案时沿用已经确定的结论与实施授权。

AI 先查能自行查到的论文、资料或代码，带着具体候选和反例来讨论。在会改变方向的地方，问用户怎么看、依据是什么、哪些条件要保留。用户已经讲清理由时直接用上；一次纠正要反映到所有受影响的结论。用户明确指定的专家搭档可以回答技术疑问；个人取舍和执行授权以用户意见为准。

## 四个核心 Skill

**问题定义。** 从直觉、现象或设想出发，核查它在什么条件下发生，影响是否重要，最近工作和简单办法能解决到哪里，还剩什么值得研究的挑战。材料可以支持立题、收窄、放弃或继续取证。完整首稿依次交付以下三问。

1. **问题是什么？** 按下面的版式呈现。摘要版每段一句，写到可以直接放进论文或 PPT。详细指南可以在两段内展开。研究前已经存在的困难写在问题段；系统将输出什么、团队要怎么做，各放回相应位置。

   **背景：** 企业评估一类陌生负载能否按时交付时，可以查看请求与设备的运行记录。

   **问题：** 当排队和传输同时发生时，仅凭各环节耗时难以判定谁实际推迟了交付，企业因而难以确定优先优化哪个环节。

2. **为什么重要？** 写清谁受到影响、影响经过什么过程产生、会改变哪个实际决定。优先给出动机测量、可信案例或原文支持的解释。适合设计动机实验时，说明负载、基线、要改变的条件、指标，以及看到什么结果会削弱动机。拟议实验标明待测。
3. **现有工作为什么失败？** 先查相关路线、最接近的论文、强简单组合、经典工作、近期进展和反例，回到原文的方法和实验。用表逐项写出代表工作和原文位置、能力与做法、在本问题下受限的条件、具体后果与证据。具有不同能力的近邻单列。对已经解决的子问题缩小主张，对仍可能推翻缺口的路线继续查，对缺乏实测的影响保留待验判断。

**研究方法。** 从现有方法的失效原因提炼根源挑战，再为各挑战寻找对应做法。需要启发时也可以先讲透其他领域的一项原理，再找目标系统中自然存在的相似条件。学术资料用于核实源头与先例，仓库、官方文档、工程文章用于核实实现和成本。用同一实例比较可行方案，说明借来的原理改变了哪个设计决定、在哪里失效，以及各部分如何组成整体。交付应有推荐理由、强简单替代、代价、最先做的判别实验和应当放弃方案的结果。做测量课题时，用一条观测走完字段关联、计算和判断。

**工程需求分析。** 到实际代码、接口、配置和测试中查清路径。用真实使用场景与用户厘清目标、非目标、约束和成功标准，让双方都能指出理解偏在哪里。交出当前最合适的实现路径、值得考虑的替代方案，以及第一步可验证、可回退的改动。验收看用户最终能做到什么。需要实现且已获授权时，实际修改、运行、检查输出并复测。

**教学。** 从用户卡住的概念和手里的材料开始。补齐必要背景，用具体对象和例子解释关键关系，再由用户预测结果、举例或应用到一个相近情境。根据实际推理定位误解并调整讲法。已有应用足以证明理解时直接推进；只请求解释时先给解释。请求保存学习笔记时，核对库内同主题内容后归档。

## 七问与下游交付

两项研究 Skill 共同维护一份《写作指南》。问题定义写问题、重要性、现有工作的缺口；研究方法接着写核心思想、设计、实验计划、预期结论。七问之后按摘要至结论列每章要讲什么、画哪些图表、每张图表能支持什么结论。另交的《实验计划》把已议定的方法写成可执行步骤，说明输入、产物、比较、验收及停止条件。改排旧稿时保留已确认的实质内容。系统或 HPC 写作 Skill 据此组织实际贡献与证据。[文件约定](../expert-skill-references/seven_question_research_outputs.md)

| 相邻工作 | 怎样验收 |
| --- | --- |
| 论文检索 | 按眼前的研究问题重组查询，说明论文贡献、假设、相关性、反证和原文核查程度。题目变了要更新检索路线。 |
| 阅读笔记 | 以论文为事实依据，可附 Markdown、已有 PPT 和讨论纠正。第一问分背景和问题，动机对应作者的理由或测量，相关工作按路线比较。按作者组织讲清设计和实验设置，图表标明位置、目的和结论，另列写作细节和启发，深度足以准备汇报。 |
| 审稿 | 分阶段形成可支撑 PPT 的分析笔记及可交付的正式意见。分析在问题、重要性、已有工作、关键思想、实验支撑五处分别给判断，第六问查写作与展示。正式意见按最新讨论、修改后的笔记和 PPT 组织，事实核原文，评分用会议档位。主要意见和小修分清，两份交付的立场一致。 |
| PPT 与归档 | 新给的模板优先，续改沿用原稿，新稿缺模板时用 BatchGen。按已确认的结构、图号、术语和论证深度核对实际页面。阅读、审稿及按要求生成的学习笔记默认存入已确认的 Obsidian 库，按内容和用途去重，历史迁移先确认清单。 |

## 要求从哪里来

本次用两个受限样例检查首答。流水线案例给定两份虚构资料，模型交付了独立的背景段、问题段、拟议动机实验和两行来源比较，并保留了“现有方法可能已够用”的判断。方法案例中，模型用同一对任务比较耗时排序、时间表和依赖图，区分了 A 等数据的 3 毫秒与 A 在所有条件就绪后额外等待的 0 毫秒。两例检查格式与推导。真实检索覆盖和现场归因仍要在具体课题中核查。
