# 笔记默认存入 Obsidian

仅用于已请求生成的阅读、审稿和学习笔记；不自动把普通回答、项目 README、实验日志、写作指南或代码文档变成笔记。不改变 Skill 的显式调用规则。

## 确认真实笔记库

- 优先使用用户明确指定的库，其次使用 `OBSIDIAN_VAULT`；本机已有默认库为 `~/Documents/PHR/obsidian_phr`，现有路径工具见 `shared/obsidian/vault_paths.py`。
- 写入前确认库目录实际存在且是用户笔记库，例如有 `.obsidian` 配置或已确认的笔记目录。必要时核对 Obsidian 注册的库，不在未知位置悄悄创建一个新库；不可访问时说明障碍，临时文件不能声称已归档。
- 用户指定其他输出路径、只要可复制文本或明确不要保存时，尊重本次要求，不额外复制进库。指定路径与默认归档冲突时不擅自双写。

## 按内容落盘

| 内容 | 默认位置，相对 vault |
| --- | --- |
| 阅读笔记 | `Research/Papers/<论文短名>/Reading/enhanced.md` |
| 审稿分析笔记 | `Research/Papers/<论文短名>/Review/analysis.md` |
| 正式审稿意见 | `Research/Papers/<论文短名>/Review/formal-review.md` |
| 用户请求的知识/学习笔记 | `Learning/<主题>/<有意义的标题>.md` |

先查已有论文目录，核实是同一篇论文后沿用其名字。不要把同名、截断短名或同编号的不同论文混在一起。旧库中的 `Review/enhanced.md` 可能是旧分析稿，先读内容再归类，不能视为新的正式意见。

路径工具中 `formal_reading_path` 对应阅读笔记，`review_analysis_path` 与 `formal_review_report_path` 分别对应两阶段评审。`formal_review_path` 仅保留旧 `enhanced.md` 路径兼容性，不能据此把新正式意见覆盖到旧分析文件。

正文按原有分析流程完成，归档不等于另写一个提纲。每篇论文、每种用途优先维护一份有效笔记；不要覆盖原始笔记、PPT、已有增强稿或其他交付物，也不要因为字节不同就自动创建时间戳、哈希或 Imported 历史副本。

## 先比较已有内容，再决定保存

1. **按论文身份和用途查库。** 搜索完整题名、短名、编号和现有目录，读取对应正文；阅读笔记、审稿分析、正式意见分开比较。文件名不同不代表不同论文，旧 `Review/enhanced.md` 也可能已经是完整正式评审，不能仅按旧文件名推断。
2. **最新修改时间优先用于查阅排序，不单独决定保留。** 对照正文日期、用户/导师最终纠正、是否为定稿及实际内容。复制、同步和格式转换会刷新 mtime，较新的样例或快照也可能比已确认笔记更旧或更差。
3. **先排除仅存储差异。** BOM、换行、frontmatter、图片和附件路径变化可能让哈希不同，却没有新增知识；图片路径变化还需核对对应图片内容。`shared/obsidian/note_dedup.py` 可做只读正文/图片比较，结果不是自动导入、合并或删除授权。
4. **逐项检查实质增量。** 按问题、动机、现有工作、思想、设计、实验、结论及用户纠正比较。库内已覆盖的解释、初稿、临时图表讲解、过时评审和模板示例不单独入库。局部新增只提出需要补充的段落与来源，不能把整份旧稿作为“新增笔记”。分数、实验数字、限定条件或结论冲突必须显式说明，不能当格式差异抹掉。
5. **历史迁移先报清单，确认后再写。** 列出每篇“沿用已有、补充具体段落、新建缺失笔记、不保留旧稿”的建议，给出已有路径、候选路径、修改时间及理由。未经确认，不批量写入笔记库；“发现库外 Markdown”不代表发现遗漏笔记。用户已明确要求新写且库内无同论文同用途笔记时，按本次要求正常保存，不人为增加确认回合。

内容是否已被吸收需要实际审阅；相似度或文本覆盖率只是定位差异，不能代替判断。用户已有笔记中的最终纠正优先于旧稿；不确定的增量保留待审，不擅自入库。旧 Codex 文件只在用户授权清理、保留内容可验证、且检查引用/生成依赖后处理；优先可恢复清理并记录原路径，不按年龄或 mtime 批量删除。

## 附件、核对与回执

- 保存后检查图片、附件、内部链接。迁入笔记库的相对路径不能继续指向已改变的位置；按库约定复制必要附件并修正链接，保留原件和论文来源。
- 对批量历史归档，先盘点、核对论文身份、审阅与已有笔记的实质差异、取得清单确认，再导入。哈希只用于完整性与完全相同副本识别。项目文件、缓存、回收/隔离目录和不明草稿不盲目导入；哈希相同也不构成删除授权。
- 重新打开最终文件，核对正文完整性和附件可访问性，运行适用的笔记质量检查；返回真实的 Obsidian 路径。不要只返回 Codex 临时目录。
- 审稿内容可能保密，只落入已确认的本地库，不因此开启云同步、上传或发布。
